# Switchframe: production switcher module

> Design rules: [`../design-rules.md`](../design-rules.md) (R3.1, R3.12–R3.15, R7.7, R8.4). This document maps
> the Switchframe module's features to the product's real configuration, for the orchestrator
> (the "compiler") that will deploy it with Docker / Terraform. MXL deployment comes later.

Source: open-source **Switchframe** (github.com/zsiec/switchframe, fork github.com/thiagopnts/switchframe),
`main@7923615` (2026-06-09). Read from its README, `docs/reference/config-and-flags.md`,
`docs/operations/deployment.md`, `docs/reference/api/*.md` and `docs/subsystems/*`.

The module is in [`catalogs/switchframe.catalog.json`](../../catalogs/switchframe.catalog.json)
(import it from the Palette). It's generated by `npx tsx scripts/product-catalogs.ts`; re-run that after
a library change. Modules aren't designed in the app: each one models a real product.

## How the product is modelled

The feature library has a **Production switcher** section with four groups. The module uses all of them.

| Group | Features (module block ids) |
|---|---|
| Switcher inputs | SRT source (`srt-src`, ×16), MoQ source (`moq-src`, ×8), MXL source (`mxl-src`, ×8), ST 2110 receiver (`st2110-src`, ×8) |
| Switcher source options | built into every input: Source setup, Audio channel, Upstream key |
| Switcher outputs | SRT program output (`srt-out`, ×8), RTMP program output (`rtmp-out`, ×4), MXL program output (`mxl-out`), ST 2110 program output (`st2110-out`), Program recording (`recording`) |
| Switcher features | Switching engine, Transitions, Audio mixer, Keyers & DVE, Downstream graphics, Colour grading, Lens correction & effects, Program encoder (H.264, HEVC, AAC), Closed captions, SCTE-35, Instant replay, Clip players, Playout channels, AI background removal, Operator comms, Control room |
| Switcher add-ons | AI speech-to-text (on captions), SCTE-104 on MXL (on SCTE-35) |

- ×N is the scale-out: how many copies of that input or output one instance may run.
- Each instance is configured in its dialog (double-click the node):
  - the **Inputs** tab sets how many of each input type, then each source's settings in sub-tabs:
    connection, Source, Audio channel, Upstream key, Network constraints, Expected payload;
  - the **Outputs** tab does the same for outputs;
  - each configurable feature has its own tab.
- Only configuration is modelled. These run-time API calls are left to the operators:
  - cut and transitions;
  - fader levels and mutes;
  - graphics on/off;
  - replay marks and playback;
  - clip and playout transport;
  - SCTE-35 cues;
  - comms;
  - DVE and preset recall;
  - macro runs.
- Features **operated live** (transitions, mixer, keyers, graphics, grading, ST map, comms) have no
  settings. They're listed so the module describes the whole product.
- Design rules:
  - the SRT/RTMP outputs and recording need the Program encoder;
  - SCTE-104 needs an MXL source or MXL program output;
  - the encoder needs at least one codec;
  - each feature is at most once per module.

## What the orchestrator decides (Docker / Terraform)

None of this is in the desired state; it's the compiler's job (R1.2).

- **Image**: `switchframe` (CPU, ~400 MB) or `switchframe:cuda` (NVIDIA, CUDA + TensorRT + ASR, ~5 GB).
  Choose CUDA when the instance's resource profile asks for a GPU, or it uses AI background removal or AI speech-to-text.
- **MXL builds**: MXL needs a build with the `mxl` tag.
- **Ports**:

  | Port | Protocol | Purpose |
  |---|---|---|
  | 8080 | UDP + TCP | QUIC/HTTP3 API and WebTransport (control room, MoQ sources) |
  | 9090 | TCP | Admin: `/metrics`, `/health`, `/ready`, `/api/cert-hash` |
  | 6464 | UDP | SRT listener, when an SRT source uses listener mode |
  | 7464–7467 | UDP | SRT output listener range, when an SRT output uses listener mode |
  | 8090 | TCP | NMOS IS-04/IS-05, when ST 2110 is used |

  Exposure follows each block's Network constraints.
- **Volumes**:
  - state dir (`SWITCHFRAME_STATE_DIR`, default `~/.switchframe`, the image's `VOLUME`);
  - cache dir (`--cache-dir`);
  - replay tmpfs (`--replay-tmpfs-dir`, `/dev/shm`);
  - recordings and clips, from the instance's storage dependencies;
  - the MXL domain (`--mxl-domain`, `/dev/shm/mxl`), shared with the other MXL functions on the host.
- **TLS**: `--tls-cert` / `--tls-key` from the facility's PKI, otherwise a self-signed cert.
- **Admin**: `--admin-addr 0.0.0.0:9090` and `--admin-token` (`SWITCHFRAME_ADMIN_TOKEN`).
- **Host tuning**:
  - `nofile` ≥ 65536;
  - `net.core.rmem_max` / `wmem_max` 128 MB;
  - GPU passthrough (`--gpus all`).
- **ST 2110**: DPDK NIC (`--st2110-port`), local IP (`--st2110-ip`), PTP mode (`--st2110-ptp`), NMOS port.
- **Resilience**: `expectations.resilience: "1+1"` becomes two engines:
  - `--engine-label a` / `b`;
  - `--peer-engine-url`;
  - `--control-plane-secret`.
- **Never in production**: `--demo` (it turns off authentication).

## Not modelled yet

- How MoQ sources are named and admitted (Prism stream naming), and whether MoQ needs a separate ingest.
- Runtime state the operator creates (presets, macros, stingers, LUTs, wipe patterns, ST maps, SCTE-35 rules):
  could be dependencies (seed files) later.
- The format presets as a design rule. Today the resolution × rate combination is checked only at compile time.

# DMF Toolkit

Front-end web UI for a DMF configuration and deployment tool. The core of the UI is a node canvas: users drop blocks onto an infinite work area, configure them, and draw wires between them.

## Guiding principle (user, 2026-10-10; refined 2026-10-11)

The **Configurator is a high-level, declarative language; the orchestrator is the compiler.** The configurator expresses the operator's intent as a desired state: workflow graph + parameters, MXL flow definitions (stable UUIDs, formats, writer/readers, history), connection topology, resource requirements, scaling/resilience expectations, placement constraints, discovery metadata. It never decides or does the imperative work: container deployment, shared-memory mounting, connection setup, host choice, replica counts, licence assignment. The orchestrator reconciles the desired state with the running system. **Contract: `docs/orchestrator-contract.md` (read first).** Still true: IP-based signals only (no SDI); sources/destinations identified by a logical `reference` on External device nodes; secrets as references; buffers as `maxLatencyMs`/`historyMs` budgets.

## Stack

- React 19 + TypeScript, Vite, oxlint
- React Flow (`@xyflow/react` v12) for the canvas
- Commands: `npm run dev` (UI, http://localhost:5173, proxies `/api`), `npm run server` (API + SQLite on :3001, `tsx watch`), `npm run build` (type-checks UI and server), `npm run lint`
- Server: Node 24 built-in `node:sqlite`, plain `node:http`; no other runtime deps. `tsx` (dev dep) runs it.
- Open `DMF Toolkit.code-workspace` in VS Code

## Layout

- `docs/orchestrator-contract.md` — **roles + what the published desired state contains** (flows, resources, expectations, placement, discovery). `src/model/workload.ts` `flowsOf`/`toPublished` implement it; flow ids = `uuidV5(metadata.uid, writer)` (`src/model/uuid.ts`).
- `docs/media-primitive.md` — the earlier model spec (v1): a primitive = deployable media function with six groups (identity/capability, placement contract, media ports, parameter JSON Schema, control/health, dependencies); the published graph (functions + port→port wires + externals); what the orchestrator derives (MXL domain/flows, flow_def.json). Read first.
- `docs/orchestration-model.md` — lifecycle/layering context, build plan, storage rules (§3–§6 superseded).
- **Hierarchy (2026-10-10, user decision):** Category → Primitive → **Vendor module**. No generic layer. Primitives (base types: port templates + shared parameter schema) live in `src/model/primitives.json` (loader/validator `src/model/primitives.ts`; review docs `docs/primitives/<category>.md`). Vendor modules (`VendorModule`, catalog entries) are created from a primitive (`moduleFromPrimitive` in `src/model/modules.ts`), name it in `role`, and must conform (`conformance()` in `catalog.ts`: ports ⊆ primitive ports with same direction/essence/side, required ports present, every primitive parameter kept with same type, enums may only narrow; vendor extras allowed). **Identity (2026-10-10):** one catalog per vendor (vendor name mandatory and unique; catalog id = `vendorSlug(vendor)`); module type id = `<catalog>.<primitive>.<n>` with `n` auto-assigned (`nextModuleId`), enforced by `catalogProblems` (`src/model/modules.ts`) on save/import; the editor shows a read-only "Module number" and vendor. DB schema v4 (`catalogs.vendor`, unique). **No infrastructure in the configurator (2026-10-10):** modules have no placement (image, CPU/memory/GPU, licences, locality, edge interfaces, node constraints); that's the orchestrator's job. Edge functions are inferred from external ports (`isEdge`). Module = identity & capability, media ports, parameters, control & health, dependencies. Replicas and storage mount paths were removed too (orchestrator decides); instances keep only their logical MXL domain. **Core + vendor settings (2026-10-11, user decision):** `parameters` = primitive's core vocabulary (minimal; may only narrow; no extras); `vendorSettings` = `{schema, mapping}` mirroring the vendor's own config names/structure, with `CoreMapping {core, vendor, values?}` from core leaf paths to vendor leaf paths. Instances carry `parameters` + `settings` (mapped keys omitted via `settingsSchema()`); `vendorConfig()` shows the merged config the orchestrator applies. Receiver (2026-10-11): one external input (`in.video` = video feed or `in.audio` = audio-only, via the template's `essenceOptions`), one protocol per **module** (primitive `protocols`; vendor with several protocols = several modules), MXL outputs locked (`whenInput` decides out.video/out.audio/out.anc). 2022-7 doubles the input into required legs `.a`/`.b` (template `dualFor`, module-level); SRT bonding adds path B per instance (port `dualWhen: {"srt.bonding": [...]}` → `resolvePorts` yields `in.video` "SRT A" + `in.video.b` "SRT B", both required). The Modules-tab node preview follows the core-parameter sandbox values. Module ports are generated by `portsFor(prim, {essence, protocol})` and checked exactly by `conformance`; the editor shows only Port + Protocol. Core parameters follow the protocol (`x-protocols`; `coreSchemaFor(prim, protocol)`): only SRT defined so far: `srt` = SRT session (`x-audience: function`, injected): mode, bonding (none/broadcast/main-backup); per-path boxes `srt.pathA`/`srt.pathB` {port, remoteAddress} and `network.pathA`/`network.pathB` {network, zone, vlan} (`x-group: paths` renders them as a pair, `x-title-when` titles them Connection/Network vs Path A/Path B; pathB `x-when` bonding; dotted x-when keys like `srt.bonding` resolve from the parameters root), latencyMs, encryption, passphrase (`x-when` encryption on), streamId, mtu; `network` = network constraints (`x-audience: orchestrator`): exposure + pathA/pathB; `payload` (`x-audience: both`): per-path pathA/pathB {bitrateMbps (required), container, videoCodec, audioCodec}; plus normalised output `video`, `audio`, `timing`. `x-when` drives SchemaForm visibility, conditional `required` in `validateValue`, and `withoutInapplicable` strips hidden values at publish. Modules may declare a vendor `resources` profile. Nodes draw a time-context group as one collapsible connection ("MXL"), auto-expanded when a member is wired alone. External devices have one `stream` port each. Decoder/Encoder still have the older 3-port external bundles. **Between functions media travels only as MXL flows; external transports exist only at edge ports facing External devices.**; other primitives not yet reduced. Categories so far: Acquisition → Receivers, Decoders, Synchronizers; Distribution → Encoders. Defined one category at a time with the user.
- `src/model/types.ts` — `MediaPrimitive`, `PortDef`, `FunctionCatalog`, `WorkloadDescription` (`apiVersion dmf-toolkit/v1alpha2`).
- `src/model/catalog.ts` — `Catalog` (all versions; `get`, `latest`, `forRole`), `resolvePorts` (port arrays → `id[i]`, bundle `group`), `wireMismatch` (essence/transport/format/constraint intersection), `checkPrimitive`/`checkCatalog`, `conformance`. Shared by UI and server.
- `src/model/schema.ts` — JSON Schema subset: defaults, validation, secret refs (`format: secret-ref` → `{"$secret": name}`).
- `src/model/workload.ts` — canvas nodes (`fn` instances, `ext` devices), `planConnection` (port or bundle wiring), `edgesFor` (wires → React Flow edges, bundles collapsed), `rebind`, `pruneWires`, `checkWorkload` (draft), `publishProblems`, `toPublished`.
- `src/model/externals.ts` — canvas-only external devices (camera, microphone, source, destination).
- `server/db.ts` (schema v3: `modules` table; migrates v2 automatically), `server/app.ts` (REST: `/api/modules`, `/api/parts`, `/api/catalogs`, workloads, `GET /api/workloads/:id/published`), `server/main.ts`.
- `src/api.ts` — API client, `refreshCatalog`, `useCatalog`.
- `src/components/MediaNode.tsx` (function/external nodes, grouped ports with bundle handles `@group`), `Palette.tsx` (by role + externals + library), `Inspector.tsx` (module choice per instance, placement, `SchemaForm` parameters, dependency bindings, contract, publish readiness), `SchemaForm.tsx`, `PartsEditor.tsx` (Modules tab: New module… from a primitive, six sections + live preview), `WorkloadBrowser.tsx`.
- `src/App.tsx` — wires are the source of truth (`Wire[]`), edges derived; New/Open/Save/Import/Export/Publish; draft in `localStorage` key `dmf-toolkit:workload:v2`.
- `src/index.css` — all styles, dark theme only (colours in `:root`; React Flow uses `colorMode="dark"`); `--kind-color` (`.fn`, `.fn.edge`, `.ext`), `--essence-color`, `--bundle-color`.
